# 기능 안내

설치와 처음 설정은 [설치 가이드](INSTALL.md)를, 요구사항별 구현 상태는 [구현 상태](requirements-status.md)를 보세요. 이 문서는 운영하면서 쓰는 기능을 정리합니다. 설정 변경은 모두 `aa config`(터미널 메뉴) 또는 Telegram 명령으로 합니다.

## 0. 메시지 이해

- **명확한 명령은 바로**: `/status` 같은 슬래시 명령, GitHub 주소, "새 프로젝트 만들어줘", 프로젝트 Topic의 분명한 작업 지시("로그인 화면 추가해줘"), 팀 의견 요청("다들 어떻게 생각해?")은 규칙으로 바로 처리합니다.
- **대화는 AI가 이해**: 질문, 아이디어, 애매한 말, 라운지에서의 작업 지시는 AI 한 명이 최근 30분 대화(사용자 말과 AI 답변)를 함께 읽고 의도를 정합니다.
  - 질문이면 같은 호출에서 바로 답합니다. 질문 때문에 AI를 두 번 부르지 않습니다.
  - 작업 지시면 직전 대화에서 정해진 내용을 포함해 작업을 정리하고, 대상 프로젝트를 고릅니다. 진행 중인 프로젝트가 하나뿐이면 그 프로젝트로 접수합니다. 예: AI가 기본값을 제안한 뒤 "알아서 만들어봐"라고 하면 그 기본값대로 첫 작업을 시작합니다.
  - 나중에 할 아이디어면 후보 목록에 저장합니다.
- **AI가 판단하지 못하면**: 실행 가능한 AI가 없거나 응답이 형식에 맞지 않으면 예전처럼 규칙으로 처리합니다.

## 1. 승인

- **승인 카드**: 작업 이름, 위험도 배지(🟢 낮음 · 🟡 중간 · 🟠 높음 · 🔴 매우 높음), 재확인 필요 여부, 요약, 만료 시각(UTC)을 한 카드에 보여 줍니다.
- **"✏️ 수정 요청"**:
  - 버튼을 누르면 같은 채팅이나 Topic에 사용자가 다음으로 보내는 메시지 하나를 수정 의견으로 받습니다. 30분이 지나면 받지 않습니다.
  - 받은 의견은 승인 기록에 남고, "최신 명시 지시"로 프로젝트 기억에 저장되어 기존 기억보다 우선합니다.
  - 의견이 들어간 뒤의 진행은 승인 종류에 따라 다릅니다.

    | 승인 종류 | 수정 의견을 받은 뒤 |
    |---|---|
    | 계획·아키텍처·범위 승인 | 의견을 요구사항에 붙여 다시 기획합니다. 분할했던 하위 작업은 취소합니다. |
    | PR 병합·핵심 기능 확인 | 수정 단계로 돌아가 같은 브랜치에 새 커밋을 올립니다. 품질 게이트와 교차 리뷰를 다시 거치고, 기존 PR에 반영 내역을 댓글로 남깁니다. PR은 새로 만들지 않습니다. |
    | 프로젝트 제안 | 제안을 보관하고 의견을 반영해 다시 제안합니다. |

- **"🛑 취소"**: 해당 작업을 중단합니다.
- **만료 알림**: 유효기간이 2시간 이상인 승인이 1시간 안에 만료되면 카드를 한 번 더 보냅니다. 운영 배포처럼 유효기간을 일부러 짧게 둔 위험 작업에는 보내지 않습니다.
- **`/approvals`**: 승인 대기 카드를 다시 받습니다. 프로젝트 Topic에서는 그 프로젝트 것만 받습니다.

## 2. 진행 표시

- **고정 진행 메시지**: 단계, 담당 AI, 현재 작업, 진행 중이거나 대기 중인 작업(최대 5건)과 차단 사유를 보여 줍니다. "⏸ 일시정지/▶️ 재개", "📊 현황", "⏳ 승인 대기" 버튼이 있고, 누를 때마다 프로젝트 소유자인지 확인합니다.
- **작업 접수 카드**: "⬆️ 우선순위 올리기"와 "🛑 취소" 버튼이 있습니다.

## 3. 에이전트: 성격과 관계

- **말투 한계**: 유머 최대치(0~1)와 반말 허용 여부를 정합니다. 반말을 끄면 친밀도가 높아도 존댓말을 유지합니다.
  - Telegram: `/agent tone <이름> humor 0.3`, `/agent tone <이름> informal off`
  - 터미널: `aa config` → 에이전트
- **`/team`**: 에이전트 쌍마다 관계 단계(알아가는 중 · 편한 사이 · 막역함), 친밀도, 협업 횟수, 최근 협업 메모를 보여 줍니다. 표현에만 쓰이며 권한이나 배정에는 영향을 주지 않습니다.

## 4. 자연스러운 진행자 말투 (선택)

진행자 AI의 안내 문장을 LLM으로 다듬어 세계관에 맞는 대화체로 바꿉니다. 기능 플래그 `dialogue.llm_renderer`로 켜며, **기본값은 꺼짐**입니다.

| 안전장치 | 내용 |
|---|---|
| 사실 보존 | 원문의 숫자, 따옴표 안 내용, URL, 코드, 경로·브랜치, #번호, @멘션이 결과에 그대로 있어야 합니다. 원문에 없던 숫자가 나와서는 안 됩니다. 길이에는 상한이 있습니다. 하나라도 어기면 정해진 템플릿 문장을 씁니다. |
| 적용 범위 | 진행자의 인사·보고·지시·오류 안내만 다듬습니다. 승인 카드, 결과 보고 카드, 시스템 메시지는 다듬지 않습니다. |
| 비용·지연 | 600자 이하만 처리하고, 결과를 캐시(500건)하며, 30초 제한을 둡니다. Local CLI 실행기만 사용합니다. |

실제 Claude CLI로 메시지당 약 4~5초가 걸려 기본값을 꺼 두었습니다. 건설현장 모드에서는 "기초공사 수준이라 걱정 안 하셔도 돼요" 같은 현장식 표현이 덧붙을 수 있습니다(새 숫자나 이름은 없음). 이런 덧붙임이 싫다면 꺼 둔 채로 쓰세요.

## 5. 안전한 중단과 업데이트

- **안전한 중단**: 종료 신호를 받으면 새 작업을 가져오지 않고, 실행 중인 작업을 `AA_SHUTDOWN_GRACE_MS`(기본 45초)까지 기다린 뒤, 끝나지 않은 실행은 실제로 취소합니다. 해당 작업은 체크포인트 단계 그대로 "대기"로 돌아가고 다음 시작 때 이어서 진행합니다. 이렇게 끊긴 실행은 실패로 보고하지 않습니다. Compose의 `stop_grace_period`는 60초입니다.
- **`/maintenance on|off`**: 켜면 실행 중인 작업은 마무리하고 새 작업은 시작하지 않습니다. 재시작해도 유지됩니다.
- **`/upgrade`**: 승인을 받으면 유지보수 모드를 켜고, 실행 중인 작업이 끝나기를 기다린 뒤(최대 2시간), 복원 검증을 마친 백업을 만들고 업데이트 시점을 알려 줍니다. 그다음 서버에서 `aa update`를 실행합니다.
- **자동 해제**: 새 버전으로 시작하면 유지보수 모드가 꺼지고 대기 작업이 재개됩니다. 같은 버전으로 재시작하면 유지보수 모드를 유지하고 그 사실을 알려 줍니다.
- 컨테이너 이미지 교체는 서버 권한이 필요하고 실패하면 되돌리기 어려워서, 앱은 안전한 시점을 만드는 데까지만 자동화합니다.

## 6. 동시 실행

- 프로젝트당 한 작업씩 실행하고, 전역 동시성은 `AA_MAX_CONCURRENT_PROJECTS`(기본 2)를 상한으로 실제 CPU·RAM·디스크에 맞춰 자동으로 줄입니다.
- 구독 CLI는 계정 단위 사용량 제한이 있어 `AA_MAX_RUNS_PER_EXECUTOR`(기본 2)로 실행기마다 동시 실행 수를 제한합니다. 넘는 실행은 순서대로 기다립니다.

## 7. 백업

- 매일 자동 백업하고 최근 7개를 보관합니다. 수동 백업은 `aa backup` 또는 `aa` 메뉴 → 지금 백업.
- 모든 백업은 만든 직후 임시 내장 PostgreSQL에 실제로 복원해 테이블별 행 수를 비교합니다. 실패하면 알림을 보내고, `backup` 명령의 종료 코드에도 반영합니다.
- 원격 백업(S3 호환)은 `aa config` → 원격 백업에서 설정합니다. 마스터 키는 백업에 들어가지 않으니 `aa key`로 따로 보관하세요.

## 8. 기존 저장소 기준선

가져온 저장소에 원래부터 실패하는 테스트가 있어도 작업이 막히지 않도록, 연결할 때 기존 코드 그대로 품질 게이트를 한 번 실행해 기준선을 저장합니다. `/baseline`으로 다시 점검합니다.

- 기준선에서 이미 실패하던 검사는 실행하고 보고하되 차단하지 않습니다. 게이트 메시지, 결과 카드, PR의 미해결 이슈에 "기존 실패(이번 변경과 무관)"로 표시합니다.
- 기준선에서 통과하던 검사가 실패하면 회귀로 보고 차단합니다.
- 이미 실패하던 검사가 다른 이유로 계속 실패하는 경우는 구분하지 못합니다. 그래서 게이트 제목에 "기존 실패 N건은 회귀 여부만 판단"을 표시하고 교차 리뷰를 계속 거칩니다.

## 9. 비밀정보 검사

품질 게이트의 첫 항목인 `secrets` 검사는 차단 항목입니다.

| 탐지 대상 | 예시 |
|---|---|
| 토큰 형식 | Telegram, GitHub, Anthropic, OpenAI, AWS, Google, Slack, 개인 키 |
| 하드코딩된 비밀값 | 비밀번호·토큰 변수에 긴 문자열을 직접 넣은 경우 |
| 민감 파일 | `.env`, 키·인증서 파일, SSH 키, 자격 증명 JSON(`.env.example` 같은 예시 파일은 허용) |

- 걸리면 수정 지시와 함께 구현 단계로 돌려보냅니다. 보고에는 파일, 줄 번호, 종류만 쓰고 비밀값은 쓰지 않습니다.
- 푸시 직전에 아직 푸시하지 않은 커밋을 하나씩 다시 검사합니다. 중간 커밋에 비밀정보가 있었다면 커밋들을 하나로 합쳐(squash) 이력에서 없앤 뒤 푸시합니다. 최종 결과에 남아 있으면 푸시하지 않습니다.

## 10. 사용량과 성과

`/usage [일수]`로 영구 저장된 실행 기록을 집계해 봅니다.

| 구분 | 항목 |
|---|---|
| 실행기별 | 실행·성공·실패·취소 수, 평균 소요 시간, 입력·출력 토큰(공급자 공식 값), API 환산 비용 |
| 에이전트별 | 완료 작업, 첫 시도 통과율, 평균 시도 횟수, 받은 리뷰 수정 요청, 평균 소요 시간 |
| 팀 협업 | 인계 횟수, 실행기 전환 횟수, 중복 실행 방지로 보류된 횟수 |

API 환산 비용은 "(추정, 구독 실제 과금 아님)"으로 표시합니다. 성과 지표는 참고용이며 필수 검증이나 리뷰를 줄이는 데 쓰지 않습니다.

## 11. 인증정보 즉시 차단

유출이 의심되면 `aa config` → 인증정보 즉시 차단에서 저장된 인증정보를 바로 막습니다. 먼저 로컬에서 사용을 막고, 발급처별로 처리합니다.

| 인증정보 | 처리 |
|---|---|
| GitHub 토큰 | GitHub의 공식 폐기 API(`POST /credentials/revoke`)를 호출하고 성공 여부를 표시합니다. 실패하면 직접 폐기하는 방법을 안내합니다. |
| GitHub App 키, Telegram 봇 토큰, 스토리지 키 | 공식 폐기 API가 없어 폐기 위치를 안내합니다. Telegram 토큰을 차단하면 봇도 멈춥니다. |

## 12. 추가 실행기: Gemini CLI, Cursor CLI

| 실행기 | 쓰는 공식 명령 | 허용하는 인증 | 기능 플래그 |
|---|---|---|---|
| Gemini CLI (`gemini-cli`) | `gemini -p … -o json`, `--approval-mode plan`(읽기 전용), `-m` | Login with Google(`oauth-personal`)만. API 키와 Vertex AI는 유료 API로 보고 쓰지 않습니다. | `executors.gemini` |
| Cursor Agent CLI (`cursor-cli`) | `cursor-agent -p --output-format json`, `--mode plan`(읽기 전용), `--resume`, `status --format json` | `cursor-agent login`(구독)만. `CURSOR_API_KEY`는 실행 환경에서 제거합니다. | `executors.cursor` |

- `aa setup`/`aa config` → AI 구독에서 고르면 로그인과 기능 플래그를 함께 처리합니다. 실제 실행 검증 기록이 생기기 전에는 자동으로 선택하지 않습니다.
- Gemini의 `-r`은 세션 ID가 아니라 순번이나 `latest`로만 재개하므로 재개는 "미지원"으로 표시합니다.
- Gemini CLI는 이미지에 기본 설치됩니다. Cursor CLI는 `aa cursor`로 공식 설치 스크립트를 써서 이미지에 추가합니다(`.env`의 `INSTALL_CURSOR_CLI=true`, `aa update` 뒤에도 유지). 로그인 정보는 볼륨에 보관합니다.

## 13. B 협업 스타일 (선택형 실험)

기능 플래그 `dialogue.style_variant_b`를 켜면 세계관마다 토론 진행 방식이 달라집니다. 기본값은 꺼짐입니다.

| 세계관 | B 방식 |
|---|---|
| 회사 | 1라운드는 제안(결론, 근거, 리스크 순서), 2라운드는 리스크 검토와 최종 권고. 최대 2라운드 |
| 건설현장 | 짧은 현장 브리핑(할 일, 막힌 것, 필요한 도움) 1라운드. 이견이 있을 때만 2라운드 |
| 대학 | 가설과 지정된 반론자의 반박을 거친 뒤 합의 라운드. 최소 2라운드 |

모든 토론의 결과에 방식(A·B), 세계관, 라운드 수, 합의 여부, 소요 시간을 기록하고 `/experiment [일수]`로 비교합니다. 바뀌는 것은 토론 구조와 표현뿐이며 승인, 품질 게이트, 권한은 같습니다.

## 14. 협업 성과 최적화 (선택)

기능 플래그 `analytics.team_optimization`을 켜면 성과 지표를 작업 배정에 반영합니다.

- **구현 담당**: 첫 시도 통과율, 실행 성공률, 현재 부하, 평균 소요 시간으로 고릅니다. 이력이 적은 에이전트는 평균값에서 시작하도록 보정합니다.
- **리뷰 담당**: 다른 공급자를 우선합니다. 후보가 여럿이면 승인한 작업이 나중에 수정 요청을 덜 받은 리뷰어를 고릅니다.
- 사용자의 @멘션이 최적화보다 우선하고, 배정 이유에 근거 수치를 보여 줍니다. 품질 게이트와 교차 리뷰는 줄이지 않습니다.

## 15. 사용자 정의 세계관

`aa config` → 사용자 정의 세계관에서 만들고, Telegram에서 `/mode custom:<ID>`로 전환합니다.

- **바꿀 수 있는 것**: 이름, 이모지, 분위기, 사용자·진행자·에이전트 호칭, 팀 전체를 부르는 호칭
- **기반 세계관**: 회사, 건설현장, 대학 중 하나에서 말투 기본값, 유머 정도, B 협업 방식을 물려받습니다.
- **관계별 말투**: 에이전트끼리의 말투(존댓말, 친해지면 반말)와 사용자에게 쓰는 말투(격식, 편한 존댓말)를 따로 정합니다. 반말을 허용해도 친밀도가 쌓여야 바뀌고, 페르소나에서 반말을 금지했다면 쓰지 않습니다.
- 사실을 꾸며내지 않기, 모욕 금지 같은 기본 규칙과 승인·품질·권한·비용 정책은 그대로입니다.
- 최대 20개까지 만들 수 있고, 삭제하면 그 세계관을 쓰던 사용자는 기반 세계관으로 돌아갑니다.

## 16. Research Agency

출처가 달린 조사·분석 보고서를 만드는 업무 유형입니다.

- **시작**: 마스터 라운지에서 조사 요청을 하면 리서치 프로젝트로 제안됩니다(예: "AI 코딩 도구 시장 조사 보고서 프로젝트 만들어줘"). `/new research <주제>`로 직접 만들 수도 있습니다. 앱, 웹, API처럼 만들 소프트웨어가 언급되면 개발 프로젝트로 분류합니다.
- **흐름**: 조사 계획, (필요하면) 승인, 조사·작성, 구조 점검, 팩트체크 교차 리뷰, 수정, PR, 사용자 확인. 개발과 같은 파이프라인을 씁니다.
- **조사·작성**: 실행기의 웹 검색·열람 도구를 허용합니다. 웹 내용은 신뢰하지 않는 데이터로 다루고 페이지 안의 지시는 따르지 않습니다.
- **구조 점검**(차단): 보고서 파일 존재, 1,200자 이상, `## 출처` 섹션에 URL 3개 이상, 본문에 [1] 형식 인용, 비밀정보 검사.
- **팩트체크 리뷰**: 출처로 뒷받침되지 않는 주장, 출처와 다른 수치·날짜, 지어낸 출처, 한쪽으로 치우친 결론을 찾습니다.
- **산출물**: 저장소의 `reports/…md`로 PR을 열고, 같은 파일을 Telegram Topic에 문서로도 보냅니다.
- 실제 Claude CLI로 Node.js·Deno·Bun 비교 조사를 실행해, 첫 시도에 구조 점검(출처 21개, 인용 21개)과 팩트체크 리뷰를 통과했습니다(약 220초).

## 설정 레퍼런스

| 설정 | 기본값 | 설명 |
|---|---|---|
| `AA_MAX_CONCURRENT_PROJECTS` | 2 | 동시에 진행할 프로젝트 수 상한(실제 자원에 맞춰 더 낮아짐) |
| `AA_MAX_RUNS_PER_EXECUTOR` | 2 | 실행기별 동시 실행 수 |
| `AA_SHUTDOWN_GRACE_MS` | 45000 | 종료 시 실행 중인 작업을 기다리는 시간 |
| `AA_BACKUP_PASSPHRASE` | (설치 시 자동 생성) | 백업 암호화. 원격 백업에 필수 |

기능 플래그는 `aa config` → 기능 플래그에서 켜고 끕니다.
